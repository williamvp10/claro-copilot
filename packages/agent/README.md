# @claro/agent

`createAgent(ports, options?)` returns an `AgentRunner`. The default implementation is deterministic and calls the server-owned `AgentPorts` only; it does not execute external business writes. `run` validates the contract, reads the server-authorized case and fixed config revision, and returns a public answer/handoff or a private advisor card. Account reads and retention evaluation happen only for a verified case in the advisor audience. A proposal is requested only on an explicit client acceptance for an identifiable option; approval and execution remain with the platform. `resume` requires the original proposal ID as `effect_id` and only reports confirmation when an effect reference is present.

Options accept a `KnowledgeAdapter` or `documents`, a typed decision adapter, a reranker and a `CheckpointStore`. Documents are filtered by scope, business date, status and channel before lexical ranking; the optional reranker can only reorder retrieved documents. The bundled catalog excerpt is from the fictional CAT-2026 v1.0 fixture and is intended for the local demo. Production must inject a published, authorized corpus with effective dates and visibility. `CheckpointStore` can persist the result by key; without one it is process-local, and the platform must preserve idempotency for proposal creation across restarts.

This implementation does not yet include LangGraph, durable graph checkpoints, Redis, MCP, pgvector/hybrid retrieval, an OpenAI adapter, a Jev provider/eval runner, Langfuse, or Deep Agents. The injected adapters provide seams for these capabilities; they are not evidence that those services are integrated. A decision adapter must sanitize inputs before sending them to a remote provider. The fallback is local and deterministic.
